# МойСклад: подготовка безопасной синхронизации

Текущий `/api/moysklad/stock` читает остатки главного склада «Береке базар». Новый `/api/moysklad/preflight` только проверяет конфигурацию. **Он не создаёт перемещений, отгрузок и списаний.**

## Настройка Vercel

Существующие переменные:
- `MOYSKLAD_TOKEN` — секретный токен МойСклад.
- `MOYSKLAD_WAREHOUSE_ID` — UUID склада «Береке базар».

Добавить:
- `MOYSKLAD_VEHICLE_WAREHOUSES` — JSON вида `{"<supabase-seller-user-uuid>":"<moysklad-vehicle-store-uuid>"}`. UUID каждого продавца и склада должны быть настоящими. Каждая машина — отдельный склад МойСклад, не совпадающий с главным.

GET `/api/moysklad/preflight` проверяет существование складов через API МойСклад, не возвращая их ID и токен. Ответ `writeEnabled:false` означает, что реальные списания не активированы.

## Что необходимо перед записью

1. Подтвердить, что у каждой машины есть отдельный склад МойСклад, и сопоставить его продавцу.
2. Определить организацию, контрагента и документ для продажи (отгрузка либо иной согласованный документ).
3. Добавить серверную авторизацию Supabase JWT и проверку роли; не доверять seller_id или количеству из браузера.
4. Ввести журнал операций с уникальным ключом, блокировками и состояниями (pending / succeeded / reconciliation_needed), чтобы повторные запросы не создавали второй документ.
5. Перенести загрузку, возврат и продажу на серверный подтверждаемый процесс. Текущие Supabase RPC сразу меняют остатки машины и **не синхронизированы** с МойСклад; их нельзя считать подтверждением перемещения.
6. Проверить одну тестовую загрузку, продажу и возврат на тестовых складах; сверить остатки, только затем разрешить реальные операции.

Не включать write API до выполнения этих шагов.
